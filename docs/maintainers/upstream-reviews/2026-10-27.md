## Absorb (S2 unless noted)

- Reproduce first and name the root cause (debugging).
- A failing test first, scoped by Ponytail's proportional test rule (TDD).
- Check a finding against the code before acting (receiving-code-review).
- Context first, one open question, 2-3 approaches with a recommendation (brainstorming 7.0.1, into the readiness gate and the planner's Approach).
- Acceptance criterion to proof mapping (writing-plans).
- A 20,000-byte skill budget test.
- The smallest-complete-change ladder in planner, implementer and reviewer.
- Review discipline: a concrete case per finding, callers, expected load, the smallest fix, a "Not checked" line.
- The `shortcut: <limit>, <trigger>` marker; `ponytail:` is still accepted.

## Adapt

- Per-task subagents become one fresh context per ticket (S3).
- Parallel dispatch becomes parallel tickets behind an independence preflight (S3).
- Headless behaviour tests become a paid manual eval protocol (S5).

## Reject

- The using-superpowers bootstrap and session hook: ceremony and double orchestration.
- Always-on brainstorming and design-doc approval: friction on clear tickets.
- Bite-sized plans with full code: token-heavy.
- executing-plans, finishing-a-branch, using-git-worktrees: TicketFlow already does these.
- diagnosing-superpowers: harness-specific; the Run line covers it.
- Ponytail hooks, band, MCP, gain/help and levels.
- ponytail-debt as a tool: `git grep -n "shortcut:"` suffices, and there is no second ledger next to issues.
- ponytail-audit: postponed, never per ticket.
- Benchmark numbers as TicketFlow evidence.
